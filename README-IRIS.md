# Experimental Iris terrain bridge for Minecraft 26.3

This opt-in prototype runs opaque/cutout terrain through Nvidium's existing task
shaders and a mesh version of the terrain program prepared by Iris. Iris/Sodium
continues to render shadows, water and other translucent terrain. It targets
Minecraft 26.3, Sodium 0.9.2 and **Iris 1.11.7**. Fabric Loader 0.20.1 was used
for validation on an RTX 3080 with OpenGL.

Reference packs: Complementary Reimagined/Unbound r5.9.3, including their
Euphoria Patches 1.10.5 variants generated by the official EuphoriaPatcher.
This is an experimental hybrid renderer, not a general compatibility guarantee.

## Enable

1. Build with JDK 25: `./gradlew build` (Windows: `gradlew.bat build`).
2. Replace the existing Nvidium JAR with the built JAR from `build/libs`.
3. Install the versions above, select the OpenGL backend and leave Nvidium's
   translucency sorting set to **Sodium**.
4. Add this **JVM argument** to the Minecraft launcher's Java arguments:

   ```text
   -Dnvidium.iris.experimental=true
   ```

5. Select a reference shaderpack in Iris. For Euphoria, install the official
   EuphoriaPatcher normally and select its generated pack.

Nvidium's debug information includes
`Experimental Iris bridge: mesh terrain; Sodium shadows/water` when the world
renderer actually uses the bridge. Pipeline initialization is also logged.
Removing the JVM argument restores the existing shader compatibility behavior.
Other Iris versions do not activate these internal mixins. Unsupported shader
conversions fall back to ordinary Iris/Sodium terrain.

## Implementation and tradeoffs

- Preserve Iris's extended terrain vertex format, including material IDs,
  normals/tangents, texture midpoints and block data.
- Convert the already Iris-patched vertex body to a per-vertex function in an
  NV mesh shader. Match fragment varyings with a named interface block.
- Re-evaluate mutable global initializers after loading each vertex, preserve
  pack extension directives ahead of declarations and keep Iris's program
  state/uniform/sampler setup.
- Use Nvidium's original primary/temporal task payloads and section origins.
- Keep Sodium's terrain meshes for its unchanged shadow and transparency
  passes. This duplicates geometry and adds CPU/upload/memory overhead.
- Bound mesh geometry storage by the driver's SSBO limit and 2047 MiB.
- Disable Sodium's chunk fade lookup in the mesh path because Nvidium owns
  section residency and does not have Sodium's section-time texture.
- Clean up programs, shader stages and buffers on reload and failure.

Chunk upload bursts can now use up to four staging buffers (32 MB each for the
world renderer). When all are busy, wait for a copy batch's fence rather than
calling `glFinish`. Sparse pages are committed only when their first mesh
references them; overlapping meshes share their residency until the last
reference is released.

These changes remove specific synchronization costs. They do not eliminate
world generation, lighting, mesh compilation or other mods' stalls. No general
FPS improvement is claimed. Arbitrary shader settings, resource packs, external
Nvidium geometry transformations and larger modpacks still need validation.

## Reproduce validation

CPU tests run with `./gradlew test`. GPU/reference tests are explicit opt-in,
require a display-capable OpenGL driver with `GL_NV_mesh_shader`, and fail if
the references are missing.

Fetch the pinned official packs and patcher and generate Euphoria references
locally (PowerShell, JDK 25 on PATH or JAVA_HOME):

```powershell
./tools/Fetch-ShaderReferences.ps1
./gradlew build '-Dnvidium.gpuTests=true'
./gradlew runIrisSmoke
./gradlew runIrisRender
./gradlew runIrisRender -PeuphoriaTests
```

The default reference directory is `../reference-packs`; override the compiler
tests' path with `-Dnvidium.referencePacks=/absolute/path`. Development render
tasks expect the default directory and run in `run-render`.

The test suite covers reference terrain/water/shadow programs in Overworld,
Nether and End, both Euphoria styles with default and PBR/colored-light
configurations, and a real GPU pixel readback. Sparse residency tests exercise
overlap, disjoint transitions and invalid releases.

The separate development smoke mod checks real Fabric/Mixin integration.
The render task creates a fresh flat world, verifies 120 staging uploads using
a deliberately tiny buffer, renders both styles alongside Sodium references,
changes dimensions, toggles shaders and observes a 20-second chunk-loading
flight. Screenshots and frame-time observations are written inside
`run-render`. The window is hidden, and a deadline terminates a stalled run.
Existing installations and saves are not used. Frame times include the 60 FPS
limiter and are functional observations, not a controlled performance benchmark.

Neither the smoke mod nor any generated shader source is included in the
release JAR. **Do not redistribute generated Euphoria/Complementary shader
sources** with this project. Download/install them from the official projects:
[Complementary Reimagined](https://modrinth.com/shader/complementary-reimagined),
[Complementary Unbound](https://modrinth.com/shader/complementary-unbound),
[Euphoria Patches](https://modrinth.com/mod/euphoria-patches).
